# 第三章：输出篇

> 大模型的输出默认是纯文本，但实际应用往往需要结构化数据。本章介绍 LangChain 的三种输出策略：字符串解析、JSON 解析、列表解析，以及自定义解析器；并深入讲解结构化输出（Pydantic）和流式输出的实战技巧。

## 3.1 输出策略（output_strategies.py）

### 知识点

| 解析器 | 输出类型 | 适用场景 |
|--------|----------|----------|
| **StrOutputParser** | 纯字符串 | 问答、翻译、写作等纯文本场景 |
| **JsonOutputParser** | Python 字典 | 结构化数据提取、表单填写 |
| **CommaSeparatedListOutputParser** | Python 列表 | 关键词提取、推荐列表、分类标签 |
| **自定义解析器** | 自定义类型 | 特殊格式需求、复杂转换逻辑 |

### 运行方式

```bash
python src/chains/output_strategies.py
```

### 示例详解

#### 示例1：StrOutputParser - 字符串输出

**场景**：角色扮演问答——选择一个角色（程序员/医生/律师/教师），以该角色的风格回答问题。

**核心代码**：

```python
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个专业的{role}，请用简洁专业的语言回答问题。"),
    ("human", "{question}")
])

chain = prompt | model | StrOutputParser()
response = chain.invoke({"role": role, "question": question})
```

**运行流程**：
1. 用户选择角色（如"程序员"）
2. 角色名注入 System Prompt，约束 AI 的回答风格
3. `StrOutputParser` 将 `AIMessage` 对象提取为纯字符串
4. 返回值可直接 `print()` 或拼接展示

**实战要点**：
- `StrOutputParser` 是最简单、最常用的解析器，直接返回字符串
- 适合不需要结构化的纯文本场景（对话、写作、翻译等）
- 可以搭配任意 PromptTemplate 使用，是 LCEL 链的"默认终点"

---

#### 示例2：JsonOutputParser - JSON 输出

**场景**：书籍分析助手——输入书名，AI 返回结构化的 JSON 分析结果（书名、作者、类型、评分、关键词等）。

**核心代码**：

```python
from langchain_core.output_parsers import JsonOutputParser
from pydantic import BaseModel, Field

# 定义期望的输出结构
class BookAnalysis(BaseModel):
    title: str = Field(description="书名")
    author: str = Field(description="作者")
    genre: str = Field(description="类型/题材")
    rating: float = Field(description="评分（1-10）")
    summary: str = Field(description="一句话总结")
    keywords: list = Field(description="关键词列表")

parser = JsonOutputParser(pydantic_object=BookAnalysis)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一位专业的书评人，请分析用户提到的书籍。"),
    ("human", "{book_name}\n\n{format_instructions}"),
])

chain = prompt | model | parser

result = chain.invoke({
    "book_name": book_name,
    "format_instructions": parser.get_format_instructions()
})
# result 是 Python 字典，可直接按 key 访问
print(result.get('title'))    # 书名
print(result.get('rating'))   # 评分
```

**运行流程**：
1. 定义 `BookAnalysis` Pydantic 模型，描述期望的 JSON 结构
2. `JsonOutputParser(pydantic_object=BookAnalysis)` 创建解析器
3. `parser.get_format_instructions()` 自动生成格式说明，注入到 Prompt 中引导 LLM 输出 JSON
4. 解析器将 LLM 的 JSON 字符串输出转为 Python 字典

**实战要点**：
- `JsonOutputParser` 会自动在 Prompt 中注入格式说明，引导 LLM 输出 JSON
- 输出为 Python 字典，可直接按 `key` 访问，无需手动解析
- 结合 Pydantic 模型可以约束字段名和类型，但运行时返回的是字典而非 Pydantic 对象
- 如果需要强类型验证，应使用 `PydanticOutputParser`（见 3.2 节）

#### 示例3：CommaSeparatedListOutputParser - 列表输出

**场景**：列表生成助手——选择领域（编程/美食/旅行/电影），输入需求，AI 生成逗号分隔的列表。

**核心代码**：

```python
from langchain_core.output_parsers import CommaSeparatedListOutputParser

parser = CommaSeparatedListOutputParser()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个{domain}专家，请根据用户需求生成相关列表。"),
    ("human", "{request}\n\n{format_instructions}"),
])

chain = prompt | model | parser

result = chain.invoke({
    "domain": domain,
    "request": request,
    "format_instructions": parser.get_format_instructions()
})
# result 是 Python 列表
for i, item in enumerate(result, 1):
    print(f"  {i}. {item}")
```

**运行流程**：
1. `CommaSeparatedListOutputParser` 自动生成格式说明，引导 LLM 输出逗号分隔的内容
2. 解析器按逗号拆分 LLM 输出，返回 Python 列表
3. 可直接遍历列表使用

**实战要点**：
- 自动按逗号拆分输出，返回 Python 列表
- 适合关键词提取、推荐列表、分类标签等数量不固定、格式简单的枚举场景
- 输出顺序由 LLM 决定，不保证排序
- 如果需要更复杂的列表结构（如嵌套列表），应使用 `JsonOutputParser`

#### 示例4：自定义解析器 - KeyValueOutputParser

**场景**：属性提取助手——输入产品描述，AI 提取为 `key=value` 格式，解析器将其转为 Python 字典。

**核心代码**：

```python
from langchain_core.output_parsers import BaseOutputParser

class KeyValueOutputParser(BaseOutputParser):
    """自定义键值对解析器：解析 key1=value1, key2=value2 格式"""

    def parse(self, text: str) -> dict:
        result = {}
        text = text.strip()
        pairs = text.replace("\n", ",").split(",")
        for pair in pairs:
            pair = pair.strip()
            if "=" in pair:
                key, value = pair.split("=", 1)
                result[key.strip()] = value.strip()
        return result

    def get_format_instructions(self) -> str:
        return "请按照 key1=value1, key2=value2 的格式输出，每对用逗号分隔。"

# 使用自定义解析器
parser = KeyValueOutputParser()
chain = prompt | model | parser
result = chain.invoke({"description": description, "format_instructions": parser.get_format_instructions()})
```

**运行流程**：
1. 继承 `BaseOutputParser`，实现 `parse()` 和 `get_format_instructions()` 方法
2. `parse()` 方法接收 LLM 的原始输出字符串，按自定义逻辑解析
3. `get_format_instructions()` 返回格式说明，引导 LLM 输出目标格式
4. 解析器将 LLM 输出转为 Python 字典

**实战要点**：
- 继承 `BaseOutputParser` 并实现 `parse()` 方法即可创建自定义解析器
- `get_format_instructions()` 非必须但推荐，能引导 LLM 输出目标格式
- 自定义解析器可处理任意非标准输出格式
- 注意 `parse()` 中的异常处理，避免解析失败导致链崩溃

### 知识点

### 示例详解

#### 示例1：人物信息提取

**场景**：输入包含人物信息的文本，AI 自动提取姓名、年龄、职业、技能、邮箱等结构化字段。

**核心代码**：

```python
from langchain_core.output_parsers import PydanticOutputParser
from pydantic import BaseModel, Field

class PersonInfo(BaseModel):
    name: str = Field(description="人物姓名")
    age: int = Field(description="年龄")
    occupation: str = Field(description="职业")
    skills: list[str] = Field(default_factory=list, description="技能列表")
    email: str = Field(default="", description="邮箱地址")

parser = PydanticOutputParser(pydantic_object=PersonInfo)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个信息提取专家。请从用户提供的文本中提取人物信息。\n\n{format_instructions}"),
    ("human", "{text}")
])

# 使用 partial 预填充格式说明
prompt = prompt.partial(format_instructions=parser.get_format_instructions())
chain = prompt | model | parser

result = chain.invoke({"text": text})
# result 是 PersonInfo 对象，可直接访问属性
print(result.name)        # 姓名
print(result.age)         # 年龄
print(result.occupation)  # 职业
print(result.skills)      # 技能列表
```

**运行流程**：
1. 定义 `PersonInfo` Pydantic 模型，每个字段用 `Field(description=...)` 描述含义
2. `PydanticOutputParser` 自动生成格式说明并注入 Prompt
3. 使用 `prompt.partial()` 预填充格式说明，避免每次 invoke 时传入
4. 解析器将 LLM 输出转为 `PersonInfo` 对象，可直接访问属性

**实战要点**：
- `Field(description='...')` 帮助 AI 理解字段含义，提高提取准确率
- `default_factory=list` 为列表字段设置默认值，避免缺失字段报错
- `PydanticOutputParser` 返回的是 Pydantic 对象（非字典），支持属性访问和类型验证
- 与 `JsonOutputParser` 的区别：返回强类型对象而非字典

#### 示例4：批量信息提取

**场景**：输入包含多个人物信息的文本，AI 一次性提取所有人物的结构化信息。

**核心代码**：

```python
from typing import List

class PersonList(BaseModel):
    persons: List[PersonInfo] = Field(description="人物列表")

parser = PydanticOutputParser(pydantic_object=PersonList)
chain = prompt | model | parser

result = chain.invoke({"text": text})
print(f"共找到 {len(result.persons)} 个人物")
for i, person in enumerate(result.persons, 1):
    print(f"{i}. {person.name} - {person.occupation}")
```

**运行流程**：
1. 定义 `PersonList` 模型，包含 `List[PersonInfo]` 字段
2. AI 识别文本中的所有人物，输出包含多个元素的列表
3. 解析器将每个元素转为 `PersonInfo` 对象
4. 可遍历 `result.persons` 访问每个人物的信息

**实战要点**：
- 使用 `List[Model]` 定义批量提取，一次调用处理多条信息
- 适合团队、组织、名单等批量信息提取场景
- AI 的提取准确率取决于文本的清晰度和模型的推理能力
- 批量提取时建议限制人物数量（如"最多提取5个人物"），避免输出过长

## 3.3 流式输出（streaming_demo.py）

### 知识点

| 概念 | 作用 |
|------|------|
| **stream() vs invoke()** | `stream()` 逐块返回，`invoke()` 等待完整响应 |
| **实时显示** | 使用 `end="", flush=True` 实现逐字输出 |
| **进度反馈** | 统计 chunk 数量、生成时间等指标 |
| **事件处理** | 监控生成过程，实时统计 Token 使用量 |

### 运行方式

```bash
python src/chains/streaming_demo.py
```

运行后进入交互式菜单，选择 1-4 运行不同示例。

---

### 示例详解

#### 示例1：基础流式输出

**场景**：创意写作——输入主题，AI 实时流式生成内容，用户无需等待完整响应。

**核心代码**：

```python
import time

chain = prompt | model | StrOutputParser()

# 流式输出
start_time = time.time()
for chunk in chain.stream({"topic": topic}):
    print(chunk, end="", flush=True)
end_time = time.time()
print(f"\n生成完成！耗时：{end_time - start_time:.2f}秒")
```

**运行流程**：
1. `chain.stream()` 返回一个迭代器，逐块生成内容
2. 每个 `chunk` 是一小段文本，使用 `print(chunk, end="", flush=True)` 实时显示
3. `end=""` 避免 print 自动换行，`flush=True` 强制立即输出
4. 生成完成后统计总耗时

**实战要点**：
- `stream()` 方法逐块返回内容，减少用户等待时间
- `end="", flush=True` 是实现实时显示的关键参数
- 适合长文本生成场景（文章、报告、故事等）

---

#### 示例2：stream() vs invoke() 对比

**场景**：用同一个主题，对比两种输出方式的时间差异和用户体验。

**核心代码**：

```python
# 方式1：普通输出
start = time.time()
result = chain.invoke({"topic": topic})
invoke_time = time.time() - start
print(result)
print(f"耗时：{invoke_time:.2f}秒")

# 方式2：流式输出
start = time.time()
for chunk in chain.stream({"topic": topic}):
    print(chunk, end="", flush=True)
stream_time = time.time() - start
print(f"\n耗时：{stream_time:.2f}秒")

print(f"时间对比：invoke={invoke_time:.2f}s, stream={stream_time:.2f}s")
```

**运行流程**：
1. 先用 `invoke()` 等待完整响应，记录耗时
2. 再用 `stream()` 逐块输出，记录耗时
3. 对比两种方式的耗时和用户体验

**实战要点**：
- `invoke()`：适合短文本、批处理场景，代码简单
- `stream()`：适合长文本、实时交互场景，用户体验更好
- 两种方式的总耗时相近，但 `stream()` 的首字延迟更低
- 实际应用中，聊天机器人应优先使用 `stream()`

---

#### 示例3：带进度显示的流式输出

**场景**：在流式输出的同时，显示进度指示器（chunk 计数、时间统计）。

**核心代码**：

```python
chunk_count = 0
start_time = time.time()

print("进度：", end="", flush=True)

for chunk in chain.stream({"request": request}):
    chunk_count += 1
    # 每10个chunk显示一个进度点
    if chunk_count % 10 == 0:
        print("●", end="", flush=True)
    # 实际内容输出
    print(chunk, end="", flush=True)

elapsed_time = time.time() - start_time
print(f"\n生成完成！耗时：{elapsed_time:.2f}秒，数据块：{chunk_count} 个")
```

**运行流程**：
1. 初始化计数器和计时器
2. 每收到一个 chunk，计数器加1
3. 每10个 chunk 显示一个进度点（●），提供视觉反馈
4. 生成完成后输出统计信息（耗时、chunk 数量）

**实战要点**：
- 可以添加自定义进度指示器（进度点、进度条、百分比等）
- 统计 chunk 数量和生成时间，帮助优化性能
- 进度显示与内容输出可以并行，互不干扰

#### 示例4：流式输出的实际应用

**场景**：三种应用场景——实时翻译、文章生成、代码生成，均使用流式输出提升体验。

**核心代码**：

```python
applications = {
    "1": {
        "name": "实时翻译",
        "system": "你是一个专业的翻译助手",
        "template": "将以下文本翻译成英文，并实时输出：\n\n{text}"
    },
    "2": {
        "name": "文章生成",
        "system": "你是一个写作助手",
        "template": "根据以下主题写一篇文章（300字），实时输出：\n\n主题：{text}"
    },
    "3": {
        "name": "代码生成",
        "system": "你是一个编程助手",
        "template": "用 Python 实现以下功能，实时输出代码：\n\n{text}"
    }
}

# 创建提示词并流式输出
prompt = ChatPromptTemplate.from_messages([
    ("system", selected_app['system']),
    ("human", selected_app['template'])
])
chain = prompt | model | StrOutputParser()

for chunk in chain.stream({"text": text}):
    print(chunk, end="", flush=True)
```

**运行流程**：
1. 用户选择应用场景（翻译/文章/代码）
2. 程序根据选择创建对应的 Prompt
3. 流式输出 AI 的生成结果
4. 不同场景的 System Prompt 和 Human Prompt 不同，但流式输出方式一致

**实战要点**：
- 流式输出适合多种应用场景：实时翻译、文章生成、代码生成
- 同一个流式输出逻辑可适配不同场景，只需更换 Prompt
- 提供即时反馈，大幅提升用户体验

## 本章小结

| 章节 | 核心技术 | 关键 API |
|------|----------|----------|
| 3.1 输出策略 | StrOutputParser / JsonOutputParser / CommaSeparatedListOutputParser / 自定义解析器 | `BaseOutputParser.parse()` / `get_format_instructions()` |
| 3.2 结构化输出 | Pydantic 模型 / PydanticOutputParser / Field / 批量提取 | `PydanticOutputParser(pydantic_object=Model)` / `prompt.partial()` |
| 3.3 流式输出 | stream() / invoke() / 实时显示 / 进度反馈 | `chain.stream()` / `end="", flush=True` |

**核心认知**：
1. **选择合适的解析器**——纯文本用 `StrOutputParser`，结构化数据用 `JsonOutputParser`，强类型验证用 `PydanticOutputParser`
2. **格式说明是关键**——`get_format_instructions()` 自动生成格式说明注入 Prompt，是让 LLM 输出结构化数据的"秘密武器"
3. **Pydantic 模型定义即约束**——`Field(description=...)` 不仅帮助 AI 理解字段含义，还提供类型验证和默认值
4. **批量提取用 List[Model]**——一次调用提取多条信息，适合团队、名单等批量场景
5. **流式输出是体验的倍增器**——`stream()` 首字延迟更低，实时交互场景应优先使用
6. **自定义解析器解决特殊需求**——当标准解析器无法满足时，继承 `BaseOutputParser` 实现自定义逻辑
