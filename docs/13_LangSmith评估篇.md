## 13.1 评估与优化概述

### 为什么需要评估

LLM 应用的输出具有随机性，仅靠人工检查不够可靠。系统化的评估可以：

| 目的 | 说明 |
|------|------|
| **质量保证** | 自动评估输出质量，确保达到标准 |
| **版本对比** | 对比不同版本的输出质量，选择最优 |
| **回归测试** | 修改后自动验证是否引入新问题 |
| **成本优化** | 评估是否可以用更小的模型达到相同质量 |

### LangSmith 评估体系

```
评估体系
├── Dataset（数据集）→ 测试用例的集合
├── Evaluator（评估器）→ 自动评估输出质量
├── LLM-as-Judge → 用大模型当裁判打分
├── 对比评估 → 对比不同版本的质量
├── Prompt 管理 → 版本控制、A/B 测试
└── 监控 → 延迟、错误率、Token 消耗
```

## 13.3 评估（langsmith_evaluation.py）

### 运行方式

```bash
python src/chains/langsmith_evaluation.py
```

程序启动后进入交互式菜单，可选择运行 4 个示例。

### 知识点

| 概念 | 说明 |
|------|------|
| **Dataset** | 数据集，存储测试用例，包含输入和期望输出 |
| **Evaluator** | 评估器，自动评估输出质量的工具 |
| **LLM-as-Judge** | 用大模型当裁判，自动给输出打分 |
| **对比评估** | 对比不同版本的输出质量 |

### 示例1：数据集管理 — 创建测试用例

**场景**：创建和管理评估数据集

**核心代码**：

```python
from langsmith import Client

client = Client()

# 创建数据集
dataset = client.create_dataset("qa-evaluation")

# 添加测试用例
client.create_examples(
    dataset_id=dataset.id,
    inputs=[
        {"question": "什么是Python？"},
        {"question": "什么是机器学习？"},
    ],
    outputs=[
        {"answer": "Python是一种高级编程语言..."},
        {"answer": "机器学习是AI的子领域..."},
    ]
)
```

**学习要点**：

- Dataset 存储测试用例，每个用例包含输入和期望输出
- 数据集可以版本管理，支持增量更新
- 适合回归测试，确保修改后输出不退化

### 示例2：评估器 — 自动评估输出质量

**场景**：使用评估器自动评估 LLM 输出的质量

**学习要点**：

- 评估器可以基于规则（如字符串匹配、长度检查）
- 也可以基于 LLM（LLM-as-Judge）
- 评估结果包含分数和解释

### 示例3：LLM 自评 — 大模型当裁判

**场景**：用大模型给输出打分

**核心代码**：

```python
from langsmith.evaluation import evaluate

def llm_judge(run, example):
    """LLM 裁判评估器"""
    judge_prompt = f"""
    请评估以下回答的质量（1-10分）：
    问题：{example.inputs['question']}
    回答：{run.outputs['answer']}
    评分标准：准确性、完整性、简洁性
    """
    score = judge_llm.invoke(judge_prompt)
    return {"score": score}

# 运行评估
evaluate(
    target=my_chain,
    data=dataset,
    evaluators=[llm_judge],
)
```

**学习要点**：

- LLM-as-Judge 适合主观性强的评估（如回答质量）
- 评分标准需要明确（准确性、完整性、简洁性等）
- 可以用多个 LLM 裁判取平均分

### 示例4：对比评估 — 版本对比

**场景**：对比不同版本的输出质量

**学习要点**：

- 对比评估同时运行多个版本
- 直观展示各版本的评分差异
- 适合 A/B 测试不同 Prompt 或模型

## 13.4 Prompt 管理（langsmith_prompt_management.py）

### 运行方式

```bash
python src/chains/langsmith_prompt_management.py
```

### 知识点

| 概念 | 说明 |
|------|------|
| **Prompt 版本管理** | 追踪 Prompt 的变化，每次修改自动保存版本 |
| **A/B 测试** | 对比不同 Prompt 的效果，选出最优版本 |
| **团队协作** | 多用户共享 Prompt 模板，统一管理 |
| **回滚机制** | 回滚到之前的 Prompt 版本，快速恢复 |

### Prompt 管理的价值

| 问题 | 没有管理的困难 | LangSmith 的解决方案 |
|------|--------------|---------------------|
| **版本混乱** | Prompt 散落在代码中，无法追踪变化 | 版本管理，每次修改自动保存 |
| **效果未知** | 修改 Prompt 后不知道效果如何 | A/B 测试对比不同版本 |
| **协作困难** | 团队成员各自维护 Prompt | 中央仓库，统一管理 |
| **无法回滚** | 改坏了无法快速恢复 | 一键回滚到之前的版本 |

### 示例1：版本控制 — 追踪 Prompt 变化

**场景**：追踪 Prompt 的修改历史

**学习要点**：每次修改 Prompt 自动保存版本，可以查看完整的修改历史。

### 示例2：A/B 测试 — 对比 Prompt 效果

**场景**：对比两个 Prompt 版本的效果

**学习要点**：A/B 测试同时运行两个版本，用评估器自动对比输出质量，数据驱动选择最优版本。

### 示例3：团队协作 — 共享 Prompt

**场景**：团队成员共享 Prompt 模板

**学习要点**：Prompt 存储在 LangSmith 中央仓库，团队成员可以查看和使用，避免重复造轮子。

### 示例4：回滚机制 — 快速恢复

**场景**：Prompt 改坏了，快速回滚

**学习要点**：一键回滚到之前的版本，回滚后立即生效，比代码回滚更轻量。

## 13.5 监控（langsmith_monitoring.py）

### 运行方式

```bash
python src/chains/langsmith_monitoring.py
```

### 知识点

| 概念 | 说明 |
|------|------|
| **监控** | 实时监控 API 调用的延迟、错误率、Token 消耗 |
| **告警** | 配置告警规则，异常时自动通知 |
| **成本追踪** | 追踪 Token 消耗和成本 |
| **仪表盘** | 数据可视化，展示监控数据 |

### 监控指标一览

| 指标 | 说明 | 优化方向 |
|------|------|---------|
| **延迟（Latency）** | 请求响应时间 | 缓存、流式输出、模型选择 |
| **错误率（Error Rate）** | 请求失败比例 | 重试、降级、输入验证 |
| **Token 消耗** | 每次调用的 Token 数 | Prompt 精简、模型选择 |
| **成本（Cost）** | Token 消耗对应的费用 | 模型选择、缓存、批处理 |
| **吞吐量（Throughput）** | 单位时间处理请求数 | 并发、worker 数量 |

### 示例1：实时监控 — 延迟与错误率

**场景**：监控 API 调用的延迟和错误率

**学习要点**：

- 延迟分布比平均延迟更有价值（P50/P95/P99）
- 错误率按类型分类（超时/限流/模型错误）
- 实时监控帮助快速发现异常

### 示例2：告警配置 — 异常通知

**场景**：配置告警规则，异常时自动通知

**学习要点**：

- 常见告警：错误率 > 5%、延迟 P95 > 10s、Token 超限
- 告警通道：邮件、Slack、Webhook
- 避免告警疲劳：设置合理的阈值和冷却时间

### 示例3：成本追踪 — Token 消耗

**场景**：追踪 Token 消耗和成本

**学习要点**：

- 按 Run 追踪每次调用的 Token 消耗
- 按时间段统计总成本
- 对比不同模型的成本效益

### 示例4：仪表盘 — 数据可视化

**场景**：监控数据的可视化展示

**学习要点**：

- LangSmith 提供内置仪表盘
- 可以自定义看板，关注关键指标
- 支持时间范围筛选和下钻分析

## 13.6 学习路径与建议

### 推荐学习顺序

```
langsmith_evaluation.py（示例1→2→3→4）
    ↓ 掌握 Dataset/Evaluator/LLM-as-Judge/对比评估
langsmith_prompt_management.py（示例1→2→3→4）
    ↓ 掌握 Prompt 版本管理/A/B 测试/团队协作/回滚
langsmith_monitoring.py（示例1→2→3→4）
    ↓ 掌握 监控/告警/成本追踪/仪表盘
```

### 核心概念掌握检查

| 阶段 | 必须掌握 | 进阶理解 |
|------|---------|---------|
| 评估 | Dataset、Evaluator | LLM-as-Judge、对比评估 |
| Prompt 管理 | 版本控制 | A/B 测试、团队协作、回滚 |
| 监控 | 延迟/错误率监控 | 告警配置、成本追踪、仪表盘 |

### 实战建议

1. **先建数据集**：评估的基础是数据集，先收集一批测试用例
2. **LLM-as-Judge 慎用**：LLM 裁判本身有偏差，关键场景仍需人工审核
3. **Prompt 管理趁早**：项目初期就使用 LangSmith 管理 Prompt，避免后期迁移成本
4. **监控必上**：生产环境必须有监控，延迟和错误率是最基础的指标
5. **告警设置合理阈值**：太敏感会告警疲劳，太迟钝会错过问题
6. **关注成本**：Token 消耗直接影响成本，定期检查成本报告

### 全流程总结

```
开发阶段：
  → 开启追踪（Tracing）→ 理解调用链路
  → 调试（Debugging）→ 定位和修复问题

质量保证：
  → 建立数据集（Dataset）→ 创建测试用例
  → 评估（Evaluation）→ 自动评估输出质量
  → Prompt 管理 → 版本控制 + A/B 测试

生产部署：
  → 部署（LangServe）→ 将 Chain 部署为 API
  → 监控（Monitoring）→ 延迟/错误率/成本
  → 告警（Alerting）→ 异常自动通知
```
