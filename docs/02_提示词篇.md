# 第二章：提示词篇

> 提示词（Prompt）是大模型应用的灵魂。好的提示词能让 AI 精准理解意图，输出高质量结果。本章介绍 LangChain 中四种核心提示词技术：SystemPrompt、DynamicPrompt、PromptTemplate 和 MessagesPlaceholder。

---

## 2.1 提示词模板（prompt_basics.py）

### 知识点

| 概念 | 作用 | 适用场景 |
|------|------|----------|
| **SystemPrompt** | 设定 AI 角色和行为规则 | 角色扮演、风格控制、输出约束 |
| **DynamicPrompt** | 动态生成提示词内容 | 个性化问候、上下文注入、时间感知 |
| **PromptTemplate** | 可复用的提示词模板 | 翻译、总结、改写等模板化任务 |
| **MessagesPlaceholder** | 消息占位符 | 对话记忆管理、历史消息插入 |

### 运行方式

```bash
python src/chains/prompt_basics.py
```

运行后进入交互式菜单，选择 1-4 运行不同示例。

### 示例详解

#### 示例1：SystemPrompt - 设定角色

**场景**：角色定制——让 AI 扮演不同角色（编程专家、数学老师、产品经理），根据角色输出风格迥异的回答。

**核心代码**：

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 定义角色模板
roles = {
    "1": {
        "name": "Python 编程专家",
        "system": "你是一位资深的 Python 编程专家。你的回答必须：\n"
                 "1. 包含可运行的代码示例\n"
                 "2. 遵循 PEP8 规范\n"
                 "3. 解释核心概念"
    },
    # ... 其他角色
}

# 创建带 System Prompt 的提示词
prompt = ChatPromptTemplate.from_messages([
    ("system", selected_role['system']),  # 系统角色设定
    ("human", "{question}")               # 用户问题
])

# 构建 LCEL 链
chain = prompt | model | StrOutputParser()
response = chain.invoke({"question": question})
```

**运行流程**：
1. 用户选择角色（1-3），程序读取对应的 System Prompt
2. `ChatPromptTemplate.from_messages()` 将 system 和 human 消息组合为模板
3. 通过 LCEL 管道 `prompt | model | StrOutputParser()` 构建链
4. 调用 `chain.invoke()` 传入用户问题，AI 按角色风格回答

**实战要点**：
- System Prompt 放在对话的第一条，设定全局行为规则
- 不同角色的 System Prompt 差异越大，输出风格差异越明显
- 可以动态切换角色，无需重新创建模型实例

#### 示例2：DynamicPrompt - 动态生成

**场景**：个性化问候——根据当前时间、用户名字、心情动态生成 System Prompt，让 AI 的回答更加个性化。

**核心代码**：

```python
# 动态获取当前时间
current_hour = __import__('datetime').datetime.now().hour
time_greeting = "早上好" if 5 <= current_hour < 12 else "下午好" if 12 <= current_hour < 18 else "晚上好"

# 动态拼接 system prompt
dynamic_system = f"""
你是一个贴心的助手。

当前信息：
- 时间：{time_greeting}
- 用户名字：{name}
- 用户心情：{mood}

请根据以上信息，生成一个温暖、个性化的问候语。
"""

# 创建动态提示词
prompt = ChatPromptTemplate.from_messages([
    ("system", dynamic_system),
    ("human", "请和我打个招呼")
])

chain = prompt | model | StrOutputParser()
response = chain.invoke({})  # 不需要额外变量，已全部内嵌
```

**运行流程**：
1. 用户输入名字和心情
2. 程序根据当前时间自动判断时段（早上/下午/晚上）
3. 通过 f-string 将时间、名字、心情注入 System Prompt
4. AI 基于动态上下文生成个性化问候

**实战要点**：
- Dynamic Prompt 通过 f-string 或字符串拼接注入动态内容
- 适合注入时间、用户信息、环境变量等运行时数据
- 让 AI 的回答更加个性化和上下文相关
- 注意：动态内容在 `invoke()` 之前就已确定，不是 LLM 运行时动态生成

#### 示例3：PromptTemplate - 模板复用

**场景**：翻译、总结、改写三种任务——定义可复用的模板，通过变量填充适配不同输入。

**核心代码**：

```python
# 创建可复用的模板
templates = {
    "翻译": ChatPromptTemplate.from_messages([
        ("system", "你是一个专业的翻译助手"),
        ("human", "将以下文本从{source_lang}翻译成{target_lang}：\n\n{text}")
    ]),
    "总结": ChatPromptTemplate.from_messages([
        ("system", "你是一个专业的总结助手"),
        ("human", "用{length}句话总结以下文本：\n\n{text}")
    ]),
    "改写": ChatPromptTemplate.from_messages([
        ("system", "你是一个专业的改写助手"),
        ("human", "以{style}的风格改写以下文本：\n\n{text}")
    ])
}

# 根据任务选择模板并填充变量
chain = templates["翻译"] | model | StrOutputParser()
result = chain.invoke({
    "source_lang": "中文",
    "target_lang": "英文",
    "text": text
})
```

**运行流程**：
1. 用户选择任务类型（翻译/总结/改写）
2. 程序选择对应的模板
3. 根据任务类型收集不同的变量（如翻译需要源语言/目标语言，总结需要句数）
4. 调用 `chain.invoke()` 传入变量，AI 按模板要求输出

**实战要点**：
- `ChatPromptTemplate.from_messages()` 支持多变量模板 `{变量名}`
- 不同任务使用不同的模板，变量名和数量可灵活定制
- 模板可复用，一次定义多次调用，提高代码复用率
- 也可使用 `ChatPromptTemplate.from_template("单字符串模板")` 创建简单模板

#### 示例4：MessagesPlaceholder - 消息占位符

**场景**：对话记忆管理——将历史对话消息插入到 Prompt 中，让 AI 记住之前的对话。

**核心代码**：

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

# 存储对话历史
conversation_history = []

# 创建带消息占位符的模板
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个有帮助的助手，会记住之前的对话"),
    MessagesPlaceholder(variable_name="history"),  # 消息占位符
    ("human", "{input}")
])

chain = prompt | model | StrOutputParser()

# 调用时传入历史
response = chain.invoke({
    "history": conversation_history,
    "input": user_input
})

# 更新历史
conversation_history.append(f"用户：{user_input}")
conversation_history.append(f"AI：{response}")
```

**运行流程**：
1. 初始化空的对话历史列表
2. `MessagesPlaceholder(variable_name="history")` 在模板中预留位置
3. 每次调用时传入 `history` 和 `input`
4. AI 的回答基于历史上下文，后续对话能"记住"之前的内容
5. 调用后将本轮对话追加到历史列表

**实战要点**：
- `MessagesPlaceholder` 用于在模板中插入消息列表
- 常用于管理对话历史，让 AI 具备上下文记忆能力
- 传入的 `history` 可以是字符串列表或 `BaseMessage` 对象列表
- 实际项目中通常配合 LangChain 的 `ConversationBufferMemory` 或 `RunnableWithMessageHistory` 使用

## 本章小结

| 技术 | 核心用途 | 关键 API |
|------|----------|----------|
| SystemPrompt | 设定 AI 角色与行为规则 | `("system", "角色描述")` |
| DynamicPrompt | 注入运行时动态内容 | f-string 拼接 system prompt |
| PromptTemplate | 可复用的模板化提示词 | `ChatPromptTemplate.from_messages()` / `from_template()` |
| MessagesPlaceholder | 插入消息列表管理对话历史 | `MessagesPlaceholder(variable_name="history")` |

**核心认知**：
1. **System Prompt 是行为的基石**——它决定了 AI "是谁"和"怎么做"，是控制输出的第一道防线
2. **模板化是工程化的关键**——PromptTemplate 将提示词从硬编码变为可复用、可维护的组件
3. **动态注入让 AI 更聪明**——通过注入时间、用户信息、环境变量等，让 AI 的回答更具上下文感知
4. **消息占位符是对话的桥梁**——MessagesPlaceholder 是实现对话记忆的基础，让 AI 从"无状态"变为"有状态"
5. **LCEL 管道统一调用方式**——所有示例都使用 `prompt | model | parser` 的 LCEL 语法，简洁且一致
