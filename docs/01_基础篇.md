# 第一章：基础篇

本章介绍 LangChain 的三大基础核心：LCEL 链式调用、模型参数调优、消息类型体系。掌握这些内容是后续学习 Agent、RAG 等高级功能的前提。

## 1.1 LCEL 链式调用（basic_chain.py）

### 知识点

| 概念 | 说明 |
|------|------|
| **LCEL（LangChain Expression Language）** | LangChain 的核心语法，用管道操作符将组件串联为处理链 |
| **管道操作符（\|）** | 类似 Unix 管道，将前一个组件的输出作为后一个组件的输入 |
| **Runnable 接口** | 所有 LCEL 组件的统一接口，支持 `invoke()`、`stream()`、`batch()` 等调用方式 |
| **invoke()** | 同步调用，返回完整结果 |
| **stream()** | 流式调用，逐块返回结果，适合长文本生成 |
| **batch()** | 批量调用，同时处理多个输入 |

### 运行方式

```bash
python src/chains/basic_chain.py
```

程序启动后进入交互式菜单，可选择运行 4 个示例。

### 示例详解

#### 示例1：简单链式调用

**场景**：用户自由问答，AI 根据提问给出回答。

**核心代码**：

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个有帮助的助手"),
    ("human", "{user_input}")
])

chain = prompt | model | StrOutputParser()
response = chain.invoke({"user_input": user_input})
```

**实战要点**：

- `prompt | model | StrOutputParser()` 是最基础的链式调用模式，三步走：**构建提示 → 调用模型 → 解析输出**
- 用户输入通过 `{变量名}` 占位符传递给模板
- `StrOutputParser()` 将模型输出（AIMessage 对象）转为纯字符串，方便直接使用
- `invoke()` 执行整条链，传入字典形式的参数

---

#### 示例2：多步骤链

**场景**：文章创作助手——先根据主题生成大纲，再根据大纲写完整文章。

**核心代码**：

```python
# 第一步：生成大纲
outline_prompt = ChatPromptTemplate.from_template(
    "请为以下主题生成一个详细的文章大纲：\n\n主题：{topic}"
)
outline_chain = outline_prompt | model | StrOutputParser()
outline = outline_chain.invoke({"topic": topic})

# 第二步：根据大纲写文章
article_prompt = ChatPromptTemplate.from_template(
    "根据以下大纲，写一篇完整的文章：\n\n大纲：\n{outline}"
)
article_chain = article_prompt | model | StrOutputParser()
article = article_chain.invoke({"outline": outline})
```

**实战要点**：

- 复杂任务拆解为多个步骤，每步独立定义链、独立调用
- **前一步的输出作为后一步的输入**：`outline` 变量既是第一链的结果，也是第二链的参数
- 每个步骤可以独立调试和优化，便于排查问题
- 适用于写作、分析、数据处理等需要多轮加工的场景

---

#### 示例3：并行链

**场景**：多维度分析——对同一段文本同时进行翻译、总结和情感分析。

**核心代码**：

```python
from langchain_core.runnables import RunnableParallel

parallel_chain = RunnableParallel(
    translation=ChatPromptTemplate.from_template(
        "将以下文本翻译成英文：\n{text}"
    ) | model | StrOutputParser(),

    summary=ChatPromptTemplate.from_template(
        "用一句话总结以下文本：\n{text}"
    ) | model | StrOutputParser(),

    sentiment=ChatPromptTemplate.from_template(
        "分析以下文本的情感（正面/负面/中性）：\n{text}"
    ) | model | StrOutputParser()
)

results = parallel_chain.invoke({"text": text})
# results 是字典：{"translation": "...", "summary": "...", "sentiment": "..."}
```

**实战要点**：

- `RunnableParallel` 同时执行多个链，**各链并行运行，互不等待**
- 每个任务用键名（如 `translation`、`summary`）标识，结果通过字典按键名取值
- 相比串行调用三次模型，并行调用可显著减少总等待时间
- 适用于需要从多个角度处理同一输入的场景

---

#### 示例4：流式输出

**场景**：创意写作实时生成——用户输入需求，AI 逐字输出内容。

**核心代码**：

```python
chain = prompt | model | StrOutputParser()

for chunk in chain.stream({"user_request": user_request}):
    print(chunk, end="", flush=True)
```

**实战要点**：

- 用 `chain.stream()` 替代 `chain.invoke()`，返回生成器而非完整结果
- 每个 `chunk` 是一小段文本，逐块打印实现"打字机"效果
- `end=""` 和 `flush=True` 确保即时显示，不换行、不缓冲
- 适用于长文本生成、聊天对话等需要实时反馈的场景，**大幅提升用户体验**

## 1.2 模型参数详解（model_parameters_chain.py）

### 知识点

| 参数 | 作用 | 范围 | 典型场景 |
|------|------|------|----------|
| **temperature** | 控制输出的随机性 / 创造性 | 0.0 ~ 2.0 | 低=确定性（代码生成），高=创造性（创意写作） |
| **max_tokens** | 限制输出的最大 token 数 | 正整数 | 控制输出长度与成本 |
| **top_p** | 核采样，只从概率累积前 p 的词汇中采样 | 0.0 ~ 1.0 | 精细控制采样范围 |
| **frequency_penalty** | 对已出现词汇施加频率惩罚，减少重复 | -2.0 ~ 2.0 | 减少重复用词 |
| **presence_penalty** | 对已出现词汇施加存在惩罚，鼓励新话题 | -2.0 ~ 2.0 | 鼓励话题多样性 |

### 运行方式

```bash
python src/chains/model_parameters_chain.py
```

程序启动后进入交互式菜单，可选择运行 5 个示例。

### 示例详解

#### 示例1：Temperature 参数

**对比**：同一问题，分别使用 `temperature=0.0` 和 `temperature=1.0` 调用模型。

**核心代码**：

```python
from langchain.chat_models import init_chat_model

model_low = init_chat_model(
    model=f"openai:{config['model']}",
    temperature=0.0,
    api_key=config.get("api_key"),
    base_url=config.get("base_url")
)

model_high = init_chat_model(
    model=f"openai:{config['model']}",
    temperature=1.0,
    api_key=config.get("api_key"),
    base_url=config.get("base_url")
)
```

**实战要点**：

| temperature 值 | 行为 | 适用场景 |
|----------------|------|----------|
| 0.0 ~ 0.3 | 输出确定性高，多次调用结果几乎相同 | 事实查询、代码生成、数据提取 |
| 0.4 ~ 0.7 | 平衡创造与稳定 | 日常对话、翻译、改写 |
| 0.8 ~ 1.2 | 输出多样化，每次结果不同 | 创意写作、头脑风暴、故事生成 |

---

#### 示例2：Max Tokens 参数

**对比**：同一问题，分别不限制长度和设置 `max_tokens=50`。

**核心代码**：

```python
# 不限制长度
model_unlimited = init_chat_model(
    model=f"openai:{config['model']}",
    temperature=0.0,
    ...
)

# 限制长度
model_limited = init_chat_model(
    model=f"openai:{config['model']}",
    max_tokens=50,
    temperature=0.0,
    ...
)
```

**实战要点**：

- `max_tokens` 不设置时，模型根据问题自由决定输出长度
- `max_tokens=50` 适合简短回答（摘要、标题生成）
- `max_tokens=500` 适合中等长度回答（文章段落）
- **核心价值**：控制输出长度 = 控制成本（token 数直接影响 API 费用）

---

#### 示例3：Top P 参数

**对比**：同一问题，分别使用 `top_p=0.1` 和 `top_p=0.9`。

**核心代码**：

```python
model_conservative = init_chat_model(
    model=f"openai:{config['model']}",
    top_p=0.1,
    temperature=1.0,
    ...
)

model_creative = init_chat_model(
    model=f"openai:{config['model']}",
    top_p=0.9,
    temperature=1.0,
    ...
)
```

**实战要点**：

| top_p 值 | 行为 | 适用场景 |
|----------|------|----------|
| 0.1 | 只从概率最高的 10% 词汇中采样，输出保守安全 | 事实问答、专业文本 |
| 0.5 | 从概率最高的 50% 词汇中采样 | 日常对话 |
| 0.9 | 从概率最高的 90% 词汇中采样，输出自由多样 | 创意写作、诗歌 |

- `top_p` 与 `temperature` 功能类似，但更精细——它直接控制候选词汇的概率范围
- 实践中通常只调整其中一个，不建议同时大幅调整两者

---

#### 示例4：Frequency Penalty

**对比**：同一问题，分别使用 `frequency_penalty=0.0` 和 `frequency_penalty=1.5`。

**核心代码**：

```python
model_no_penalty = init_chat_model(
    model=f"openai:{config['model']}",
    frequency_penalty=0.0,
    ...
)

model_penalty = init_chat_model(
    model=f"openai:{config['model']}",
    frequency_penalty=1.5,
    ...
)
```

**实战要点**：

| frequency_penalty 值 | 行为 |
|----------------------|------|
| 0.0 | 无惩罚，允许重复用词 |
| 1.0 | 轻微惩罚，减少高频词的重复出现 |
| 2.0 | 强惩罚，几乎避免重复用词 |

- 正值越大，已出现过的词再次出现的概率越低
- 适用于长文本生成时避免"车轱辘话"，让表达更丰富
- 注意：设置过高可能导致语句不通顺

---

#### 示例5：Presence Penalty

**对比**：同一问题，分别使用 `presence_penalty=0.0` 和 `presence_penalty=1.5`。

**核心代码**：

```python
model_no_penalty = init_chat_model(
    model=f"openai:{config['model']}",
    presence_penalty=0.0,
    ...
)

model_penalty = init_chat_model(
    model=f"openai:{config['model']}",
    presence_penalty=1.5,
    ...
)
```

**实战要点**：

| presence_penalty 值 | 行为 |
|---------------------|------|
| 0.0 | 无惩罚，允许重复讨论同一话题 |
| 1.0 | 轻微惩罚，鼓励引入新话题 |
| 2.0 | 强惩罚，强制转向新话题 |

- `presence_penalty` 与 `frequency_penalty` 的区别：
  - **frequency_penalty**：按出现**次数**惩罚——出现越多，惩罚越重
  - **presence_penalty**：按是否**出现过**惩罚——只要出现过就惩罚，不关心次数
- 适用于需要广泛覆盖多个话题的场景（如头脑风暴、多角度分析）

## 1.3 消息类型（message_types_demo.py）

### 知识点

| 消息类型 | 作用 | 典型用法 |
|----------|------|----------|
| **SystemMessage** | 设定 AI 的行为规则和角色 | 放在消息列表首位，定义全局行为 |
| **HumanMessage** | 表示用户输入 | 每次用户提问时创建并追加到消息列表 |
| **AIMessage** | 表示 AI 回复 | 模型返回后手动追加到消息列表，保持上下文 |
| **ToolMessage** | 表示工具执行结果 | 需关联 `tool_call_id`，手动构建 |

### 运行方式

```bash
python src/chains/message_types_demo.py
```

程序启动后进入交互式菜单，可选择运行 7 个示例（含消息类型识别和格式转换）。

### 示例详解

#### 示例1：SystemMessage

**场景**：设定 AI 为 Python 编程助手，规定回答风格。

**核心代码**：

```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

messages = [
    SystemMessage(content="你是一个专业的 Python 编程助手。你的回答必须：\n"
                         "1. 简洁明了\n"
                         "2. 包含代码示例\n"
                         "3. 遵循 PEP8 规范")
]

messages.append(HumanMessage(content=user_input))
response = model.invoke(messages)
messages.append(AIMessage(content=response.content))
```

**实战要点**：

- SystemMessage **必须放在消息列表的第一位**，后续所有对话都会遵循此设定
- 可定义角色（"你是…"）、行为规则（"必须…"）、输出格式（"以 JSON 格式返回"）等
- 一旦设定，整个对话周期内持续生效，无需重复声明

---

#### 示例2：HumanMessage

**场景**：多轮对话——用户连续提问，AI 记住之前的交流内容。

**核心代码**：

```python
messages = [SystemMessage(content="你是一个友好的助手，能记住用户信息")]

# 每轮对话
messages.append(HumanMessage(content=user_input))
response = model.invoke(messages)
messages.append(AIMessage(content=response.content))
```

**实战要点**：

- 每次用户输入都创建一个 `HumanMessage` 并追加到 `messages` 列表
- 模型调用时传入完整的 `messages` 列表，模型据此理解上下文
- 对话结束后可遍历 `messages` 查看完整对话历史
- 关键：**消息列表是模型的"记忆"**，不追加就会"遗忘"

---

#### 示例3：AIMessage

**场景**：对话历史管理——自动保存 AI 回复，实现上下文连续。

**核心代码**：

```python
# 调用模型
response = model.invoke(messages)
print(f"AI：{response.content}")

# 关键：保存 AI 回复到消息历史
messages.append(AIMessage(content=response.content))
```

**实战要点**：

- AIMessage **不会自动追加**到消息列表，必须手动 `messages.append(AIMessage(content=response.content))`
- 标准四步流程：
  1. 初始化 `messages = [SystemMessage(...)]`
  2. 追加用户消息 `messages.append(HumanMessage(content=...))`
  3. 调用模型 `response = model.invoke(messages)`
  4. 保存 AI 回复 `messages.append(AIMessage(content=response.content))`
- 遗漏第 4 步是最常见的错误——模型会"忘记"自己说过的话

---

#### 示例4：ToolMessage

**场景**：工具调用流程——用户问天气，模型调用天气工具，返回结果后生成最终回复。

**核心代码**：

```python
from langchain_core.messages import ToolMessage
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """获取天气信息"""
    weather_data = {"北京": "晴天，15°C", "上海": "多云，18°C"}
    return weather_data.get(city, "未找到城市")

# 绑定工具到模型
model_with_tools = model.bind_tools([get_weather])

# 第一步：用户提问
messages = [
    SystemMessage(content="你是一个助手，可以使用 get_weather 工具查询天气"),
    HumanMessage(content="北京今天天气怎么样？")
]

# 第二步：模型决定调用工具
response = model_with_tools.invoke(messages)
messages.append(response)  # 保存含 tool_calls 的 AIMessage

# 第三步：执行工具，创建 ToolMessage
for tool_call in response.tool_calls:
    if tool_call['name'] == 'get_weather':
        tool_result = get_weather.invoke(tool_call['args'])
        tool_message = ToolMessage(
            content=tool_result,
            tool_call_id=tool_call['id']  # 必须匹配！
        )
        messages.append(tool_message)

# 第四步：模型基于工具结果生成最终回复
final_response = model_with_tools.invoke(messages)
```

**实战要点**：

- ToolMessage 是整个工具调用流程中最容易出错的环节
- **`tool_call_id` 必须与模型返回的 `tool_call['id']` 一致**，否则模型无法关联
- 完整流程四步：用户提问 → 模型请求工具 → 执行工具并构建 ToolMessage → 模型生成最终回复
- 工具调用时，含 `tool_calls` 的 AIMessage 也必须追加到消息列表

## 本章小结

### 三大核心要点

1. **LCEL 是 LangChain 的核心语法**
   - `prompt | model | parser` 一行代码构建处理链
   - `RunnableParallel` 实现并行，`stream()` 实现流式
   - 所有组件遵循统一的 Runnable 接口

2. **模型参数决定输出质量**
   - `temperature` 控制创造性与确定性——事实查询用低值，创意写作用高值
   - `max_tokens` 控制输出长度与成本——生产环境中务必设置
   - `frequency_penalty` 减少重复用词，`presence_penalty` 鼓励新话题

3. **四种消息类型是对话的基础**
   - `SystemMessage` 定义全局行为，`HumanMessage` 传递用户输入
   - `AIMessage` 保存 AI 回复，`ToolMessage` 承载工具结果
   - 对话历史靠消息列表维护，**AI 回复必须手动追加**
