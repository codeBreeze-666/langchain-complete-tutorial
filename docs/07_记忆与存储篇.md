# 第七章：记忆与存储篇

## 7.1 对话记忆（checkpointer.py）

### 知识点：对话缓冲、对话摘要、对话窗口、会话管理、持久化

**运行方式：**

```bash
python src/chains/checkpointer.py
```

**核心概念：**

| 记忆策略 | 原理 | 适用场景 | Token消耗 |
|---------|------|---------|----------|
| 对话缓冲 | 保存全部对话历史 | 短对话（客服、问答） | 随对话增长 |
| 对话摘要 | 将长对话压缩为摘要 | 长对话（咨询、访谈） | 可控 |
| 对话窗口 | 只保留最近 N 轮 | 持续对话（闲聊、快速问答） | 固定上限 |
| 会话管理 | 多会话隔离+持久化 | 多用户/多功能场景 | 取决于策略 |

**三种记忆策略对比：**

```
对话缓冲：[消息1, 消息2, 消息3, ..., 消息N]         ← 全部保留
对话摘要：[摘要] + [缓冲区消息]                       ← 压缩旧消息
对话窗口：[消息N-3, 消息N-2, 消息N-1, 消息N]          ← 只留最近N轮
```

### 示例1：对话缓冲 — 保存完整对话历史

**功能说明：** 使用 `ConversationBuffer` 保存全部对话历史，最简单的记忆策略。

**关键代码：**

```python
class ConversationBuffer:
    def __init__(self):
        self.messages = []
        self.system_prompt = None

    def add_user_message(self, content):
        self.messages.append(HumanMessage(content=content))

    def add_ai_message(self, content):
        self.messages.append(AIMessage(content=content))

    def get_messages(self):
        result = []
        if self.system_prompt:
            result.append(SystemMessage(content=self.system_prompt))
        result.extend(self.messages)
        return result

    # 序列化/反序列化（用于持久化）
    def to_dict(self): ...
    @classmethod
    def from_dict(cls, data): ...
```

**实战要点：**

1. 最简单的记忆策略，保留所有上下文，**短对话效果最佳**
2. 长对话会超出 Token 限制，需注意控制
3. 序列化后可持久化到文件（`to_dict` / `from_dict`）
4. 适合客服、问答等对话轮数有限的场景

### 示例2：对话摘要 — 将长对话压缩为摘要

**功能说明：** 使用 `ConversationSummary` 将历史对话压缩为摘要，适合长对话场景。缓冲区消息数达到阈值时自动触发摘要。

**关键代码：**

```python
class ConversationSummary:
    def __init__(self):
        self.buffer = []       # 当前对话缓冲
        self.summary = ""      # 已生成的摘要
        self.llm = get_default_llm()

    def summarize(self):
        """将缓冲区对话压缩为摘要"""
        conversation = "\n".join(
            f"{'用户' if isinstance(m, HumanMessage) else 'AI'}: {m.content}"
            for m in self.buffer
        )
        context = f"已有摘要：{self.summary}\n\n" if self.summary else ""
        prompt_text = f"{context}请将以下对话内容压缩为简洁的摘要：\n\n{conversation}"
        self.summary = self.llm.invoke([HumanMessage(content=prompt_text)]).content
        self.buffer = []
        return self.summary

    def get_messages(self):
        """获取消息列表（摘要 + 当前缓冲）"""
        result = []
        if self.summary:
            result.append(SystemMessage(content=f"对话历史摘要：{self.summary}"))
        result.extend(self.buffer)
        return result
```

**自动摘要触发机制：**

```python
SUMMARIZE_THRESHOLD = 6  # 缓冲区消息数达到此值时触发

if len(memory.buffer) >= SUMMARIZE_THRESHOLD:
    memory.summarize()
```

**实战要点：**

1. 额外调用 LLM 生成摘要，有额外开销
2. 适合长对话场景（心理咨询、深度访谈等）
3. 摘要会丢失部分细节，重要信息可能被压缩
4. 可设定触发摘要的阈值（如缓冲区消息数达到 N 条）

### 示例3：对话窗口 — 只保留最近N轮对话

**功能说明：** 使用 `ConversationWindow` 只保留最近 N 轮对话，Token 消耗可控。

**关键代码：**

```python
class ConversationWindow:
    def __init__(self, window_size=4):
        """window_size: 保留的对话轮数（一轮 = 一条用户 + 一条 AI）"""
        self.window_size = window_size
        self.messages = []

    def add_user_message(self, content):
        self.messages.append(HumanMessage(content=content))
        self._trim()

    def add_ai_message(self, content):
        self.messages.append(AIMessage(content=content))
        self._trim()

    def _trim(self):
        """裁剪超出窗口的消息"""
        max_messages = self.window_size * 2  # 每轮两条消息
        if len(self.messages) > max_messages:
            self.messages = self.messages[-max_messages:]
```

**实战要点：**

1. Token 消耗可控，窗口大小决定上限
2. 适合持续对话场景（日常闲聊、快速问答等）
3. 早期对话会被丢弃，无法回忆远处信息
4. 窗口大小需根据实际场景调整（默认3轮，6条消息）

## 7.2 跨会话存储（store_basics.py）

### 知识点：键值存储、用户偏好、共享上下文、持久化存储

**运行方式：**

```bash
python src/chains/store_basics.py
```

**核心概念：**

> **Store vs Memory 的区别**：Memory 是对话级别的记忆（随会话结束可能消失），Store 是跨会话的持久化存储（独立于对话存在）。

| 存储类型 | 核心机制 | 典型用途 |
|---------|---------|---------|
| 键值存储 | 命名空间隔离的键值对 | 配置、缓存、元数据 |
| 用户偏好 | 按用户ID隔离偏好数据 | 个性化回复 |
| 共享上下文 | 频道隔离 + 追加式上下文 | 多 Agent 协作 |
| 持久化存储 | 文件系统持久化 | 生产环境数据保存 |

---

### 示例1：键值存储 — 存储和检索键值对数据

**功能说明：** 使用 `KeyValueStore` 实现支持命名空间隔离的键值对存储，是构建更复杂存储的基础。

**关键代码：**

```python
class KeyValueStore:
    def __init__(self):
        self._data = {}  # namespace -> {key -> value}

    def put(self, namespace, key, value):
        """写入键值对"""
        self._data.setdefault(namespace, {})[key] = value

    def get(self, namespace, key, default=None):
        """读取键值对"""
        return self._data.get(namespace, {}).get(key, default)

    def delete(self, namespace, key):
        """删除键值对"""
        ...

    def list_keys(self, namespace):
        """列出命名空间下所有键"""
        ...
```

**实战要点：**

1. Store 是最基础的跨会话存储抽象
2. 命名空间隔离不同业务的数据（如 `user_preferences`、`shared_context`）
3. 适合存储配置、缓存、元数据等结构化数据
4. 是构建更复杂存储（偏好、上下文）的基础

### 示例2：用户偏好 — 记住用户的偏好设置

**功能说明：** 使用 `UserPreferenceStore` 管理用户偏好，支持手动设置、AI 自动提取和基于偏好的个性化回复。

**关键代码：**

```python
class UserPreferenceStore:
    NAMESPACE = "user_preferences"

    def set_preference(self, user_id, category, value):
        """设置用户偏好"""
        key = f"{user_id}:{category}"
        self.store.put(self.NAMESPACE, key, {"value": value, "updated_at": ...})

    def extract_preferences_from_text(self, user_id, text):
        """使用 LLM 从用户输入中自动提取偏好"""
        prompt = ChatPromptTemplate.from_template(
            "从以下用户输入中提取偏好设置。请以 JSON 格式输出..."
        )
        chain = prompt | self.llm | StrOutputParser()
        result = chain.invoke({"text": text})
        prefs = json.loads(result)
        for category, value in prefs.items():
            self.set_preference(user_id, category, str(value))

    def build_preference_prompt(self, user_id):
        """构建偏好上下文提示（注入到对话 prompt 中）"""
        prefs = self.get_all_preferences(user_id)
        lines = [f"- {k}: {v}" for k, v in prefs.items()]
        return "用户偏好设置：\n" + "\n".join(lines)
```

**个性化对话流程：**

```
用户输入 → 提取偏好 → 保存偏好 → 构建偏好上下文 → 注入 prompt → 个性化回复
```

**实战要点：**

1. 偏好存储是 Store 的典型应用场景
2. LLM 可自动从对话中提取偏好并保存（如"我喜欢简洁的回答" → `style: 简洁`）
3. 偏好作为上下文注入提示词，实现个性化回复
4. 偏好数据可持久化，实现跨会话的个性化体验

### 示例3：共享上下文 — 多Agent共享的上下文信息

**功能说明：** 使用 `SharedContextStore` 实现多 Agent 共享的上下文信息，支持频道隔离和追加式上下文。

**关键代码：**

```python
class SharedContextStore:
    NAMESPACE = "shared_context"

    def set_context(self, channel, key, value):
        """设置频道中的上下文"""
        store_key = f"{channel}:{key}"
        self.store.put(self.NAMESPACE, store_key, {"value": value, ...})

    def append_context(self, channel, key, entry):
        """追加式上下文（增量记录）"""
        existing = self.get_context(channel, key, "")
        timestamp = datetime.now().strftime("%H:%M:%S")
        new_entry = f"[{timestamp}] {entry}"
        updated = existing + "\n" + new_entry if existing else new_entry
        self.set_context(channel, key, updated)

    def chat_with_context(self, channel, user_input):
        """基于共享上下文进行对话"""
        context = self.build_context_prompt(channel)
        prompt = ChatPromptTemplate.from_template("{context}\n\n{question}")
        chain = prompt | self.llm | StrOutputParser()
        return chain.invoke({"context": context, "question": user_input})
```

**实战要点：**

1. 共享上下文是 Agent 协作的基础设施
2. 不同 Agent 通过**频道**读写同一份上下文
3. 追加式上下文适合记录日志、进度等增量信息
4. LLM 可基于共享上下文做出更智能的决策

### 示例4：持久化存储 — 将数据保存到文件

**功能说明：** 使用 `PersistentStore` 将 KeyValueStore 的数据持久化到 JSON 文件，按命名空间分文件存储。

**关键代码：**

```python
class PersistentStore:
    STORAGE_DIR = "store_data"

    def save_namespace(self, namespace):
        """将命名空间数据保存到文件"""
        data = self.store.get_namespace(namespace)
        file_path = os.path.join(self.STORAGE_DIR, f"{namespace}.json")
        with open(file_path, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)

    def load_namespace(self, namespace):
        """从文件加载命名空间数据"""
        file_path = os.path.join(self.STORAGE_DIR, f"{namespace}.json")
        with open(file_path, "r", encoding="utf-8") as f:
            data = json.load(f)
        for key, value in data.items():
            self.store.put(namespace, key, value)

    def save_all(self):
        """保存所有命名空间"""
        for namespace in self.store.list_namespaces():
            self.save_namespace(namespace)
```

**实战要点：**

1. 持久化是 Store 从内存走向生产的关键步骤
2. 按命名空间分文件存储，避免单文件过大
3. 启动时自动加载，关闭时自动保存
4. 文件格式使用 JSON，便于查看和调试
5. 退出前提示用户保存，避免数据丢失

## 本章小结

本章深入探讨了 LangChain 中记忆与存储两大主题：

1. **对话记忆**：掌握了三种记忆策略——对话缓冲（全量保留，短对话首选）、对话摘要（压缩旧消息，长对话利器）、对话窗口（固定窗口，Token 可控），以及会话管理器（多会话隔离 + 持久化存储）。核心是理解不同策略的权衡：完整上下文 vs Token 消耗。

2. **跨会话存储**：学习了键值存储（命名空间隔离的基础存储）、用户偏好（LLM 自动提取 + 个性化注入）、共享上下文（多 Agent 协作的频道机制）和持久化存储（文件系统持久化）。核心是理解 Store 与 Memory 的区别——Store 独立于对话存在，是跨会话的持久化数据。

**关键原则：**
- 选择记忆策略要根据对话长度和 Token 预算：短对话用缓冲，长对话用摘要，持续对话用窗口
- 持久化是生产环境的必备能力，确保重启后数据可恢复
- Store 适合存储结构化数据（配置、偏好、共享状态），Memory 适合存储对话历史
- 用户偏好可以让 AI 回复更个性化，共享上下文可以让多 Agent 协作更智能
